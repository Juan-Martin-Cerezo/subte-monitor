# SUBTE Monitor: Buenos Aires Transit Live Tracking

**Entrega:** Proyecto Informático 13/07 · 2026

**URL en vivo:** [https://subte-monitor.vercel.app](https://subte-monitor.vercel.app)

---

## Resumen

Sistema de monitoreo en tiempo real de la red de subterráneos de Buenos Aires. Consume la API oficial GTFS-RT del GCBA y visualiza la posición estimada de cada formación sobre un mapa interactivo, con predicciones de arribo, alertas de servicio, y un planificador de rutas.

---

## Stack Tecnológico

| Capa | Tecnología |
|------|-----------|
| Frontend | Next.js 16 (Turbopack, App Router) · React 19 · Tailwind CSS v4 |
| Tiempo real | GTFS Realtime · Algoritmo de clustering DBSCAN 1D · IDs estables |
| Mapa | Leaflet.js con interpolación de posición sobre shapes GTFS |
| Backend | API Routes (Next.js) |
| Base de datos | PostgreSQL (Neon) · Prisma ORM |
| Deploy | Vercel (serverless) |

---

## Funcionalidades

| Pantalla | Descripción |
|----------|------------|
| **Mapa** | Leaflet con trenes en movimiento, coloreados por línea. Pin de seguimiento. |
| **Arribos** | Cuadro de próximos trenes filtrable por línea, con ETA en tiempo real. |
| **Estado** | Alertas oficiales del GCBA + reportes de usuarios. |
| **Estaciones** | Malla de estaciones con datos de accesibilidad y pasajeros. |
| **Planificador** | Rutas óptimas entre estaciones (Dijkstra), filtro step-free. |

### Adicional
- Reporte colaborativo de incidencias (POST `/api/reports`)
- Mapa responsivo con bottom nav mobile
- Premetro (ramales Cívico y Savio)
- ID de tren estable aunque haya demoras severas (ventana de 10 min)

## Arquitectura Rápida

```
┌─────────────┐     ┌──────────────┐     ┌───────────────┐
│  Next.js 16  │ ──→ │  /api/telemetry │ ──→ │  GCBA GTFS-RT  │
│  (SSR + CSR) │     │  /api/bootstrap │     │               │
│              │     │  /api/reports   │     │  PostgreSQL   │
│  Leaflet map │     └──────────────┘     │  (Neon)       │
│  Dashboard   │                          └───────────────┘
└─────────────┘
```

- **Cliente**: Polling cada 2s a `/api/telemetry`. Cache server-side 1.5s.
- **Clustering**: Las predicciones por estación se agrupan en "trenes virtuales" usando proyección temporal + DBSCAN.
- **Anti-teleport**: El progreso queda congelado en 95% hasta que la API confirma el arribo.

## Anden

Anden is the assistant layer of `subte-monitor`. It answers questions about the Buenos Aires subway from the same live data the app shows: official alerts, upcoming trains, trip routes, station access and a written knowledge base. A hand-written harness plans each question, calls a small set of tools, enforces a per-question budget and stores every step as a trace. It runs locally without a database.

Three questions it answers:

- ¿Está andando la línea B ahora?
- ¿Hasta qué hora funciona el subte?
- ¿Cuánto sale el boleto de subte?

The MCP server is a separate package: [packages/subte-mcp](packages/subte-mcp/README.md). Architecture, the five stages, the measured limits and the local commands: [docs/anden.md](docs/anden.md).

## Cómo correr local

```bash
git clone https://github.com/Juan-Martin-Cerezo/subte-monitor.git
cd subte-monitor
cp .env.local.example .env.local   # completar credenciales
npm install
npx prisma generate
npx prisma db push
npx prisma db seed
npm run dev
```
